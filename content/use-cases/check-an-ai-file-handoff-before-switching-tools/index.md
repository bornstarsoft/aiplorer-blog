## Check What The Recipient Can Use

An AI handoff summary can report that a file was exported without
checking whether the recipient can open, edit or recover it. Separate
the export receipt from the evidence that work can continue.

This text-only exercise uses fictional handoff records. There are no
real files, accounts, permission changes or tool migration results.

## Review Three Handoff Boundaries

| Case | What the draft overlooked | What to check before accepting |
| --- | --- | --- |
| HAND-01 | A successful export receipt is treated as a working file. | The recipient could not open it in the destination. Retest a permitted export in that application. |
| HAND-02 | A link that opens for the sender is assumed to open for the recipient. | The approved recipient was denied. Use the approved access process; do not make the link public. |
| HAND-03 | A successful spot check is treated as authorization to remove the original. | Owner sign-off and a recovery check are still pending. Retain the original under the stated handoff rule. |

Record the exact missing check. For HAND-03, the destination test
passed, but the removal decision is still on hold. Neither fact cancels
the other.

## Compare A Later Run

Reuse the same three records. Compare whether the two answers preserve
the observed test result, the blocker and the next permitted check.
Record a baseline if no comparable first answer exists.
